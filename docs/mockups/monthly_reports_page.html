1Two new file types

Recognised on Add files / Add folder like every export: the customer workbook by its “Monthly Summary” sheet, the register by its “CPTW No / Issue Date” header. They land in the same files table and are copied into the month.

The group says what each file does to the report and what happens without it. Neither is required: missing never blocks Generate.

“Permits issued to” is a project setting edited here, because it only matters when the register is in front of you.

Unchanged: required types, “Customer POI file”, the month-end checklist.

5Alarm history as its own step

Runs by itself after the alarms file is read for coverage. The button is for a re-run (for example after exclusion windows change: it re-tags the month's stored alarms).

2Three new question kinds

Permit without PM record: a PM/KKS permit naming RMU-nn, no PM record for that block in the permit's dates. The SCADA stop is quoted, because that is what the missing record costs.

PM record without a stop: no out-of-operation run 07:00–19:00 (the same rule that lets a PM cover its stop). Says when no permit exists either and names the record it probably duplicates.

PM record without PTW No.: only when the register has the number, and the button offers it.

All three are ⚠ (confirm to generate over them). Missing register or SCADA file: the matching questions are skipped, one ℹ line says so.

RMU number = plant block 1–70. Never translated through zones.

4Two types, appended

The type only labels a window: excluded hours are summed over all types, so a window gives the same availability under any type.

Two things read the type by name and stay tied to “Scheduled Maintenance”: the report row “Scheduled unavailability (PM)” and the planner's last-PM date. KKS work is not PM, so neither picks it up.

The hint under the combo changes with the type (one line each).
